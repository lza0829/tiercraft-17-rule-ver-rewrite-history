# 05-tiercraft（筑层）

筑层 — 数仓分层建设台：贴源入仓 → 明细清洗标准化 → 汇总落表 → 层间行数/键对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流按序落库，**不是** 质检隔离签发。
**也不是** 报表看板 / CRUD 后台 / 电商订单前台 / OA 工单。

## 启动

```bash
docker compose up --build
```

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=..\data
uvicorn app.main:app --reload --port 10500

# 前端
cd frontend
npm install
npm run dev
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://localhost:5500 |
| 接口 | http://localhost:10500 |

## 主链

登记清洗规则包版本 → 选定启用版本 → 登记主题域 → 贴源层装载夹具 → 按启用版本裁决入明细层（未通过行进拒收清单）→ 汇总层聚合 → 层间对账报告与各层列表数字同源

## 规则包与版本

- 规则包按版本登记，登记后内容不可改；同一时刻仅一个启用版本，可随时切换。
- 规则必须覆盖三类：必填空值、金额下限、品类白名单；缺类登记会被拒绝。
- 贴源到明细只按**当前启用版本**裁决：通过行写入明细并带本次版本号，未通过行写入拒收清单（规则编号、原因、贴源引用 `贴源#id`）。
- 切换启用版本只影响之后的新任务；历史明细行保留产出时的版本号，不会被改写。
- 同一版本重跑会替换该版本自己的明细/拒收/汇总产物，旧任务标记「已被任务 #N 替代」。
- 任务报告可从「分层任务」按任务查看，输入 / 写入 / 拒收与明细、拒收清单、启用版本逐项核对。

默认启用一套 `v1` 规则：必填门店名称、金额不小于 0、品类限饮料/零食。
夹具中 `S03`（门店名为空）、`S04`（品类日用）、`S05`（金额 -18）会被拒收，其余 5 行进入明细。

## 界面约定

页面文案全部中文；分层称「贴源层 / 明细层 / 汇总层」，界面不出现英文缩写站名。
